# Module completion and rebuild decision matrix

Current snapshot: 2026-11-02. **Implemented and verified** means current live read verification plus relevant automated tests, not production acceptance. **Implemented but not fully verified** means source and tests exist but live end-to-end proof is missing. **Partially implemented** means important business steps are absent. **Not implemented** means no dedicated workflow/schema found. **Technically defective** means a concrete failing check or defect exists. **Blocked by configuration or external approval** means the path is gated by unset policy/configuration. Decisions: keep as-is, keep but refactor, partially rebuild, fully rebuild, defer. No rebuild was performed.

`P` below means PHP feature test source exists; `N` means Next Node tests. Tests were inspected; Laravel database-changing tests were not rerun in this audit. “Live” is limited to the current working system or clearly marked historical report evidence.

## Cross-cutting decision summary

**Keep as-is:** small, stable category/brand and supplier CRUD and indicative quote behavior, subject to the stated browser acceptance. **Keep but refactor:** core product, inventory, IMEI, POS, purchasing, shifts and most Ecommerce services; reduce service size and improve contracts without changing semantics. **Partially rebuild:** expenses/accounting reports and bank-transfer fulfillment. **Fully rebuild as a new module:** customer repair jobs, since an inventory damage workflow is not a repair business system. **Defer:** warranty and bank delivery fulfillment until business rules are approved. Do not fully rewrite the current platform: it would put existing stock, IMEI, sale and historical data at avoidable risk.
